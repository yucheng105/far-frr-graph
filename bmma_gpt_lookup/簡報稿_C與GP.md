# 簡報稿：C 怎麼來、和 GP 的關係（FaceForensics++）

只講 FaceForensics++。140 支真片、560 支偽片。這段停在「三個 C 算出來」。15 種排列的查表下一階段再講。

圖的檔案：

- `bmma_gpt_lookup/output/ffpp_conb/product_vs_threshold.png`
- `bmma_gpt_lookup/output/ffpp_conb/far_frr_bound.png`

---

## 第 1 頁　今天這段在做什麼

畫面上只放三句：

- 一個偵測器，在 FaceForensics++ 上有一張門檻表
- 從這張表算出一個常數 C
- GP 要用 C，才能把門檻算出來

口頭：

我們今天還沒有在排三個偵測器的順序。先把 GP 需要的輸入準備好。輸入是三個數字：UCF 一個 C、Xception 一個 C、SBI 一個 C。它們都只代表 FaceForensics++ 這一批影片。

---

## 第 2 頁　整個流程

畫面上放五個箭頭，不要放公式：

```text
每支影片的分數
    → 門檻表（一條曲線）
    → 每個門檻的 FAR × FRR
    → 取出常數 C
    → GP 用 C 決定排隊時的門檻
```

口頭，對照每一格：

1. 分數早就在 CSV 裡。一支影片經過 UCF，得到 0 到 1 的分數，愈高愈像假片。這段不重跑模型。
2. 把門檻從 0.05 放到 1.00。每個門檻數一次：假片有多少比例被放行（FAR），真片有多少比例被擋下（FRR）。這張表就是曲線。
3. 每一格把 FAR 和 FRR 相乘。
4. 這些乘積裡最大的那個，就是 C。
5. GP 不自己發明 C。它拿到 C 之後，才去選每一關的門檻。

C 不是最終答案。最終答案是門檻和查表。C 是中間那一站。

---

## 第 3 頁　門檻表長什麼樣子

畫面上放 UCF、門檻 0.20 這一格就好：

| | 比例 | 大約幾支 |
|---|---:|---:|
| 假片被放行（FAR） | 0.4% | 2 / 560 |
| 真片被擋下（FRR） | 54% | 76 / 140 |

口頭：

門檻設 0.20 的意思是：分數低於 0.20 就當真片放行。560 支假片裡大約只有 2 支分數這麼低，所以漏抓很少。140 支真片裡大約 76 支分數達到 0.20，被擋下來，所以誤擋很多。

門檻拉高，漏抓會變多，誤擋會變少。整張表就是在記錄這個交換。UCF、Xception、SBI 各有一張，所以 FaceForensics++ 有三條曲線、三個 C。

---

## 第 4 頁　C 的做法

畫面上放四步：

1. 每個門檻算一次 FAR × FRR
2. 找出最大的那個乘積
3. 另外算 EER 的平方（FAR 和 FRR 交會的地方）
4. 兩者取比較大的，那個數就是 C

口頭：

第 3 步是在跟交會點比一下，避免只看乘積時漏掉。FaceForensics++ 這三條曲線比完，都是最大乘積比較大，所以 C 就是最高的那一格。

結果：

| 偵測器 | C | 最高點在哪個門檻 | 那一格在說什麼 |
|---|---:|---:|---|
| UCF | 0.0032 | 0.60 | 假片約 14/560 被放行，真片約 18/140 被擋下 |
| Xception | 0.0041 | 0.70 | 假片約 32/560，真片約 10/140 |
| SBI | 0.0403 | 0.20 | 假片約 109/560，真片約 29/140 |

C 愈小，代表這條曲線愈緊、偵測器在這批影片上愈準。UCF 最小，SBI 大約是 UCF 的 12 倍。

請念到小數第四位即可：0.0032、0.0041、0.0403。表裡的精確值是 0.003214、0.004082、0.040319。

---

## 第 5 頁　第一張圖：為什麼要放

圖：`product_vs_threshold.png`

這張圖的工作：讓人看見 C 是一條天花板。

畫面上除了圖，只加三句：

- 每個點是一個門檻的 FAR × FRR
- 虛線是 C
- 紅點貼在虛線上，其他點都在線下

口頭：

如果沒有這張圖，C 只是算出來的一個小數，看不出它跟資料的關係。

這張圖回答兩件事。第一，虛線在所有點的上面或剛好碰到，所以用 C 去估計錯誤率不會估得太好看，這叫保守。第二，紅點剛好碰到虛線，C 再調低，紅點就會跑到線的外面，所以這條天花板已經是最低的一條，這叫緊密。

它不是說每個門檻的乘積都等於 C。UCF 大部分點在 0.001 到 0.003 之間，只有門檻 0.60 碰到 0.0032。

左右兩端掉到 0，是因為漏抓或誤擋有一邊變成 0，不是那個門檻特別好。

---

## 第 6 頁　第二張圖：為什麼要放

圖：`far_frr_bound.png`

這張圖的工作：說明 GP 真正用的不是上一張的水平線。

畫面上除了圖，只加兩句：

- 每個點仍是一個門檻，但這次橫軸是 FAR、縱軸是 FRR
- 虛線是 FRR = C / FAR

口頭：

上一張圖證明 C 是天花板。GP 不能把「天花板」直接拿去解門檻。它需要的是：我如果把這一關的 FAR 定成某個數，FRR 最多是多少。那就是把天花板改寫成

```text
FRR = C / FAR
```

這條虛線就是改寫之後的樣子。實測的點在虛線上，或在虛線下面。紅點貼住虛線，因為那一格的乘積就是 C。

所以兩張圖都要留。第一張說明 C 怎麼從資料取出來。第二張說明這個 C 要怎麼交進 GP。少了第二張，聽的人會以為 GP 是在看一條水平線。

SBI 右邊有些點離虛線較遠，代表那些門檻的乘積比 C 小，上界比較鬆。它仍然沒有跑到虛線上面。

---

## 第 7 頁　C 和 GP 怎麼接起來

畫面上放一個例子，不要放 15 種：

```text
排隊：UCF → Xception → SBI

GP 帶進去的 C：
  第 1 關 UCF      用 0.0032
  第 2 關 Xception 用 0.0041
  第 3 關 SBI      用 0.0403

GP 對每一關先選一個 FAR
再用紙上的公式換成 FRR：這一關的 FRR = 這一關的 C / 這一關的 FAR
```

口頭：

一次 GP 只排一種順序。順序裡有幾個偵測器，就帶幾個 C。上面這個例子是 3 個。若只用 UCF，就只帶 0.0032 這一個。

GP 的目標可以先講成一句話：在「整條隊伍的漏抓不超過我們訂的上限」的前提下，讓誤擋的上界盡量低。它調整的是每一關的 FAR。FRR 不用另外調整，因為 C 已經把它定死了。

解完之後，還要把 FAR 查回真正的門檻數字，例如 0.60。那一步是下一階段。今天先說明 C 是這一步的燃料。

FaceForensics++ 總共會做 15 次 GP：一個人 3 種、兩個人 6 種、三個人 6 種。15 次共用今天這三個 C，不會每次重算。

---

## 第 8 頁　這段的結論

畫面上三行：

- FaceForensics++ 的三個 C：UCF 0.0032、Xception 0.0041、SBI 0.0403
- C 是每條曲線的最高乘積，紅點貼住上界
- GP 用 FRR = C / FAR，所以第二張圖才是它要的關係

口頭收尾：

今天交出的是三個常數，以及兩張圖說明它們沒有估太鬆、也沒有估得比資料好看。下一頁才會用這三個數去跑排隊。Celeb-DF 和 DFDC 的曲線不同，C 也要重算，不能沿用今天這三個。
