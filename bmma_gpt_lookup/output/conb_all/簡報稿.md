# 簡報稿：三個資料集的 C

圖在 `bmma_gpt_lookup/output/conb_all/`。九張圖的結構一樣，簡報放兩張當例子，其餘留著被問再翻。主結果是 `conb_summary.csv` 那張表。

---

## 第 1 頁　這段在算什麼

畫面上三句：

- 一個偵測器、一個資料集，得到一個 C
- 三個偵測器 × 三個資料集 = 九個 C
- C = 格子上最大的 FAR×FRR，和 EER²，取比較大的

口頭：

這段還沒有跑 GP，也沒有排隊伍。我們先把 GP 以後要吃的常數算完。FaceForensics++、Celeb-DF、DFDC 各算各的，沒有把三條曲線拼成一條。

C 是 `FAR × FRR` 的天花板。有了它，才能寫 `FRR = C / FAR`。數字愈小，這批影片上這個偵測器的上界愈緊。

---

## 第 2 頁　一張圖怎麼讀

放 `celebdf_sbi.png`。三欄從左到右就是計算順序。

口頭：

左邊是門檻掃描。橫軸是門檻，紅線是 FAR，藍線是 FRR。門檻拉高，偽片比較容易被放行，FAR 上升；真片比較少被擋下，FRR 下降。直的虛線是 EER，FAR 和 FRR 交會的地方。Celeb-DF 的 SBI 大約在門檻 0.57，EER 約 0.26。

中間把每一格的 FAR 乘上 FRR。綠線是乘積，紅點是最大的那一格，約 0.0709。紫色點線是 EER 的平方，約 0.0669。因為最大乘積比較大，黑色虛線 C 就落在 0.0709。標題寫「C 來自最大乘積」。

右邊把同一批點改成橫軸 FAR、縱軸 FRR。虛線是 `FRR = C / FAR`。紅點貼住虛線，其他點在線下。GP 以後用的就是這條虛線，不是中間那條水平線。

九張圖都是這三欄，只是資料集和偵測器不同。

---

## 第 3 頁　九個 C

把表貼上。口頭可以只念到小數點後三位。

| 資料集 | UCF | Xception | SBI |
|---|---:|---:|---:|
| FaceForensics++ | 0.0032 | 0.0041 | 0.0403 |
| Celeb-DF-v2 | 0.0873 | 0.0783 | 0.0709 |
| DFDC | 0.1093 | 0.1253 | 0.1134 |

口頭：

FaceForensics++ 的 C 最小。UCF 和 Xception 只有 0.003、0.004，SBI 是 0.040，大約是前兩個的十倍。

Celeb-DF 三個偵測器都在 0.07 到 0.09，彼此接近，但已經比 FaceForensics++ 的 UCF 大二十倍以上。

DFDC 更大，三個都在 0.11 到 0.13。所以同一個偵測器不能三個資料集共用一個 C。UCF 在 FaceForensics++ 是 0.0032，在 DFDC 是 0.109。

---

## 第 4 頁　什麼時候改用 EER²

放 `dfdc_xception.png`。

口頭：

九條裡面有七條，C 等於格子上的最大乘積。只有 DFDC 的 Xception 和 SBI，EER 平方比格子上的最大乘積還大一點，所以 C 改用 EER²。

以這張為例。中間的紅點是門檻 0.50 的乘積，0.1243。EER 大約在門檻 0.48，落在 0.45 和 0.50 兩格中間，表上沒有這一列。交會點的 FAR 和 FRR 都約 0.354，乘起來是 0.1253。若只取紅點，天花板會低一點，交會點附近就破洞。所以 C 用 0.1253。DFDC 的 SBI 同樣，最大乘積 0.1124，EER² 是 0.1134，C 用 0.1134。

差不到 0.001。這一步是避免格子沒踩到交會點，不是把 C 整個換一套算法。

---

## 第 5 頁　這張表之後怎麼用

畫面上三行：

- 每個資料集帶自己的三個 C 去跑 GP
- 一種排隊有幾個偵測器，就帶幾個 C
- 這段還沒有解門檻

口頭：

例如只做 DFDC、隊伍是 UCF 再接 Xception，GP 就帶 0.1093 和 0.1253。FaceForensics++ 的 0.0032 不能放進這條隊伍。

GP 仍是：在整條隊伍的 FAR 不超過我們訂的上限時，把 FRR 壓低。每一關用 `FRR = C / FAR`。那是下一步，今天的九張圖是在把這九個輸入定下來。

---

## 被問到可以這樣答

資料從哪來？  
UCF、Xception 用 `results/20/` 的門檻表。SBI 的 FaceForensics++ 用 `threshold_sweep_sbi_faceforensics_v1.csv`，Celeb-DF 和 DFDC 用 `results/20/sbi/`。沒有用檔名帶 combined 的曲線，也沒有重跑模型。

FAR、FRR 怎麼算？  
FAR 是偽片被放行的支數除以偽片支數。FRR 是真片被擋下的支數除以真片支數。

為什麼 C 愈小愈好？  
C 小，同樣的 FAR 換成的 FRR 上界比較低，公式比較不會把誤擋估得很大。

為什麼不平均三個資料集？  
三個資料集的 C 差一個數量級。平均或逐點取最差，會做出一條沒有任何資料集長這樣的曲線。
